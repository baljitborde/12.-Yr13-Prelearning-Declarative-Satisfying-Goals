Goals and the Inference Engine
● ~10 minutes

In Part 1 you wrote facts and rules. Now you will use them. A goal is a question you ask the knowledge base. The inference engine tries to satisfy the goal by matching it against the clauses, working from the top of the knowledge base to the bottom.

The knowledge base used on this page
A small airline flies between five airports. London and Rome are hubs. A flight(A, B) fact means there is a direct flight from A to B (flights only go one way). An airport is regional if it is not a hub. You can get from X to Z with one stop if there is a flight from X to some airport Y and a flight from Y to Z.
The airline knowledge base
01 airport(london). 02 airport(paris). 03 airport(madrid). 04 airport(rome). 05 airport(berlin). 06 hub(london). 07 hub(rome). 08 flight(london, paris). 09 flight(london, madrid). 10 flight(paris, rome). 11 flight(madrid, rome). 12 flight(rome, berlin). 13 regional(X) IF airport(X) AND NOT hub(X). 14 onestop(X, Z) IF flight(X, Y) AND flight(Y, Z).
Dark boxes are hubs. Arrows show the direction of each flight.
TermMeaning
GoalA question to be satisfied, e.g. hub(X)
InstantiationA variable being given a value, e.g. X = london
BacktrackingGoing back to try the next matching clause, to find more answers

Goals with No Variables
● ~15 minutes
Quick recap: A goal with no variables is a yes/no question. It succeeds (true) if it matches a fact exactly, or can be proved by a rule. Otherwise it fails (false). Because of the closed-world assumption, anything that is not in the knowledge base is false.

Goals with Variables
● ~20 minutes
Quick recap: When a goal contains a variable, the inference engine finds every value that makes the goal true. Each time a clause matches, the variable is instantiated and the value is returned; the engine then backtracks to look for more matches further down.

Satisfying Goals with Rules
● ~20 minutes
Quick recap: When a goal matches the head of a rule, the inference engine must satisfy every condition in the rule's body, from left to right. If a later condition fails, it backtracks to an earlier condition and tries the next possible value.
Tracing the goal onestop(london, Z) using rule 14
14 onestop(X, Z) IF flight(X, Y) AND flight(Y, Z).
StepWhat the engine doesResult
1Matches the goal with the head of rule 14, so X = londonX = london
2First condition flight(london, Y): clause 08 matchesY = paris
3Second condition flight(paris, Z): clause 10 matchesZ = rome ✓ output
4Backtracks to the first condition and finds the next match, clause 09Y = madrid
5Second condition flight(madrid, Z): clause 11 matchesZ = rome ✓ output
6Backtracks again: no more flights from London, so the search endsfinished

Result: Z = rome, rome. Rome is returned twice, because there are two different routes (via Paris and via Madrid). The engine reports every way it can satisfy the goal.

NOT in a goal: for regional(X), the engine takes each airport in turn from clauses 01 to 05, then checks NOT hub(X). London and Rome fail the NOT; Paris, Madrid and Berlin succeed.
✎ Worked exam-style question
Explain how the inference engine finds the first result for the goal regional(X). [3]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • Matches the goal with the head of rule 13 / tries airport(X) first and instantiates X = london (clause 01)
  • NOT hub(london) fails because hub(london) is a fact (clause 06), so it backtracks
  • Tries X = paris (clause 02); hub(paris) cannot be found, so NOT succeeds and paris is returned
Examiner tip: Name the clauses and the values of X at each step. Use the word "backtracks".

Writing Goals and Rules
● ~15 minutes
Quick recap: In the exam you may be asked to write a goal that answers a question, or to write a new rule and then a goal that uses it. To write a goal: choose the predicate, put the values you know in their argument positions, and put a variable where the answer should go.
A new rule
// New rule: a flight that lands at a hub 15 hubflight(X, Y) IF flight(X, Y) AND hub(Y).
GoalResult
hubflight(X, Y)X = paris, Y = rome; X = madrid, Y = rome
hubflight(london, Y)false (London only flies to Paris and Madrid)
hubflight(paris, rome)true

✓ Summary — CIE 9618 Topic 20.1: Declarative Programming (Part 2)
Goals: a goal is a question. With no variables it returns true or false; with variables it returns every value that satisfies it.
Search order: the inference engine works through the clauses from top to bottom, so answers come back in clause order.
Closed world: anything not in the knowledge base, and not provable by a rule, is false.
Instantiation: when a clause matches, each variable is given a value, e.g. flight(london, X) gives X = paris, madrid.
Rules and backtracking: conditions are checked left to right. If one fails, the engine backtracks to an earlier condition and tries the next value.
Writing goals: known values in lower case in the right argument position, and a capital-letter variable where the answer goes.
